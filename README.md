# Shadow Run

A local web app that runs Shadowrun 6th Edition sessions with Claude as the Game Master, played by a group around one laptop.

- The GM runs through the `claude` CLI in headless mode (`claude -p`), so it uses your Claude login rather than an API key.
- Dice can be rolled physically and reported in the app, or rolled in the app with an animation.
- Key story beats get a generated scene image in a hand-painted 1980s arcade-animation style.

## Trying the table

The table has two parts, each in its own terminal, both started from this folder:

```
npm run dev:server      # terminal 1: the table, with Claude as the GM on your own plan
npm run dev:web         # terminal 2: its screen; then open http://localhost:5173
```

For a try that costs no usage, start the table with `SHADOWRUN_GM=scripted npm run dev:server`. If the page says "Lost the table", the server in terminal 1 is not running; the page keeps retrying and joins as soon as it is. Instead of the browser you can play from the command line with `npm run play` in a second terminal.

The screen shows the story, lets any character speak (one person types for everyone), and puts each roll the GM asks for on a card: stakes, pool and what it needs up front, with what happens and the Edge advice opening on a click. A roll can be made with the app's dice (they tumble, then the result drops into the story), with dice rolled by hand (one box per die, or paste them all into the first), skipped (not for rolls that resist damage or defend), or replaced by a Smackdown after a confirmation. The side panel shows a card for each player character with their physical, stun and overflow bars, the dice their wounds cost, their Edge points and whether they are down or dead (click a name to speak as them), then the opposition, with a group of grunts as one row that opens to each grunt. While a fight is on it is one list in acting order, the cards and grunt rows each carrying their place (1, 2, 3 …) and the round at the top; anyone not in the order follows. Every chip and abbreviation has a tooltip that opens on hover, focus or tap, and changes in how hurt anyone is are announced to screen readers. A roll card has an Edge section, closed until opened, with the GM's advice, Edge before the roll (Edge dice, or making 2s count against an opposition) and Smackdown. When Edge could be spent on a roll, rolling shows the dice first, with the opposition's, and a player either keeps the roll as it stands or spends Edge on it (reroll dice, add 1, buy a hit, reroll the misses), each with its cost and a reason when it cannot be paid for; the roll is saved with the game, so a restart in between loses nothing. With no Edge to spend, or Edge already spent this round, a roll counts at once. A roll with a declared Edge Action takes the round's one expenditure, so the other options are closed. Each player card has a "Spend Edge" menu for the ways to spend Edge off a roll: give an ally 1 Edge (2, in a fight), clear a box of stun (3) or physical damage (4), add 3 to initiative from the next round (1, in a fight), or create a special effect (5, described in a box, which the GM then decides); each shows its cost, and one that cannot be used says why. It warns if a roll with a declared Edge Action is waiting, since spending Edge there makes that action fail. A roll to resist damage is kept back to show its dice even with no Edge to spend, as long as there is Edge rank to burn; if the dice as they stand would kill, the panel says so and offers Burn Edge: Not Dead Yet, after a confirmation that states the cost for good and that the blow still lands, leaving the character unconscious and dying, one box short of dead. A link at the top of the page jumps to the typing box.

Claude plays the GM through the `claude` command-line tool, so it needs to be installed and logged in to your plan. No API key is used. Type `/help` in the client for its commands: `/start` begins the session, `/app` rolls a pending roll with the app's dice, and `/dice 6 5 3 1` reports dice you rolled at the table.

Settings, all optional:

| Variable | Default | What it does |
| --- | --- | --- |
| `SHADOWRUN_GM` | `claude` | `scripted` uses a short demo script instead, which spends no usage |
| `SHADOWRUN_GM_MODEL` | `sonnet` | the model that plays the GM |
| `SHADOWRUN_GM_EFFORT` | the CLI's own | `low`, `medium`, `high`, `xhigh` or `max` |
| `SHADOWRUN_CAMPAIGN` | `default` | which campaign folder to use |
| `PORT` | `8787` | where the table listens |

`npm run check:gm` plays a short scene with the real GM and checks it behaves: it asks for rolls with real stakes, keeps to the consequences it declared, refuses to be told what the dice said, and recovers when its session is lost. It uses a little of your plan's usage. It runs the GM at `low` effort unless `SHADOWRUN_GM_EFFORT` says otherwise (the server itself uses the CLI's own default).

The table keeps count of everyone's health using the rulebook's condition monitors: physical, stun and overflow, with a die lost on every roll except resisting damage for each filled row of three boxes. When the GM hurts someone, the system takes the damage, the player rolls their own Body to resist it (or the system does for a non-player character), and only what gets through is applied. Skipping that roll is not allowed, and a character whose monitor is full cannot act.

Edge is tracked for each player, who starts a session (each time the server starts) with Edge points equal to their Edge attribute. A player spends it on their own rolls: the 4-Edge boost that adds the Edge attribute to the pool and makes 6s explode is chosen when answering a roll, and the boosts that change dice afterwards (reroll a die for 1, add 1 to a die for 2, buy a hit for 3, reroll every die that missed for 4) are used by asking to hold the roll, which counts the dice and waits for the player to spend Edge or keep it. Everything random in Edge, the explosions and the rerolls, can be rolled by hand and reported, or left for the app; the system checks the counts. Only one expenditure of Edge is allowed per round (in a fight), or per roll (outside one), and Edge above the attribute goes away when a fight ends. The GM is told what was spent. Edge is also gained, but only in a confrontation, which the GM runs with `start_combat` whether it is a fight, a hack or a social contest: the GM gives each attack's Attack Rating and the target's Defense Rating, and when they are four or more apart a player on the stronger side gets a point of Edge before the dice are rolled (a group of grunts counts one rating higher for each member beyond the first); the GM can also award a point with `award_edge` and a reason the players read. A player who is given Edge for an attack and then skips it has it taken back. A player can gain at most two Edge a round and hold seven in all, and Edge above the attribute goes away when the confrontation ends. Non-player characters do not use Edge, so what an opponent's side of a rating gap would earn is dropped. Edge can also be spent off the roll: 2 to give an ally 1 (in a confrontation), 3 or 4 to heal a box of stun or physical damage, 1 to add 3 to your initiative from the next round, and 5 to create a special effect, which the GM then decides and narrates; and 5 before an opposed roll to make 2s count toward the opposition's glitch. The book's twelve Edge Actions are declared by a player before the roll they go with, and the GM passes the action's id on `request_roll` or `attack`: the system refuses it when the player cannot pay or has already spent Edge that round, takes the cost when the roll counts, and allows no other Edge on that roll. Called Shot: Vitals (5 Edge) adds 3 to the Damage Value of an attack that hits, and Called Shot: Disarm (5 Edge) makes a hit do no damage and knock the weapon away; the system applies both to a player's own attack. The other ten are left to the GM to carry out, with the book's description in the report, and whether what an action needs is true in the story is the GM's call. A player can also burn Edge, a last resort that permanently costs a point of Edge rank and every Edge point on hand, and works even in a round Edge was spent. Only the player chooses it. Smackdown is chosen on the roll card instead of rolling: it is an automatic success with four net hits, so an attack lands for four more damage and a defense beats the attack; it cannot be used to resist damage or heal, or with an Edge Action. Not Dead Yet is chosen on a held roll to resist damage that would kill (a roll to resist damage can be held even with no Edge points to spend, as long as there is rank to burn): the damage still lands, but stops one box short of death, so the character lives, unconscious and dying, and the GM is told they are still in danger.

Fights have an order. The GM starts one with `start_combat` and names everyone in it, and the system rolls initiative: Reaction + Intuition plus the initiative dice, with a player character's numbers taken from their sheet and a non-player character's supplied by the GM. The highest score goes first, and ties go to Edge (a grunt's Professional Rating counts as theirs), then Reaction, then Intuition, then a coin fixed when they were rolled. Grunts the GM puts in one group roll once and act together. The order stands from round to round, `next_round` advances the counter, `join_combat` lets reinforcements in without moving anyone (grunts who join together form a group of their own), and the GM is told the round and the order, with who is down, at the start of every turn. The system does not track which actions a character has spent, and wounds do not change a score, since the book gives no number for that.

Nameless opposition are grunts, as in the book: the GM names them with a Professional Rating, and each has one condition track of 8 plus half the higher of Body and Willpower (a lieutenant adds their rating), a die lost every two boxes, and dead or unconscious according to what hit them last. When damage first takes a standing grunt past their Professional Rating the system tests their nerve (Willpower + Charisma, against a threshold of 2 that is the system's own ruling) and tells the GM whether they hold or bolt. Up to five grunts can attack together as one group, which adds a die for every odd-numbered member beyond the first. Grunts cannot be healed. The shared Edge pool the book gives a group of grunts comes with Edge.

Healing needs a roll too. The GM asks for First Aid, a medkit, a healing spell or a character's own natural recovery with `request_roll`'s `healing` field, and the system sets the difficulty from the patient's Essence as the book does. When the result comes back the GM is told how many hits it has to spend with `heal` in that turn: First Aid heals a stun box per hit or a physical or overflow box per 2 hits, a medkit and healing magic a box per hit, natural recovery a box of its own track per hit, and a healer must heal overflow first. First Aid, a medkit and healing magic can each be received once until the patient is hurt again. The book's time limits (a minute, an hour, a day) are the GM's to keep, since the game tracks no time.

Attacks are settled by the GM's `attack` tool: the system rolls the attacker's pool against the defender's, an attacker with no hits misses, and a hit adds its net hits to the weapon's Damage Value before the target resists with Body. A player character rolls their own side on the screen (defending against an attack cannot be skipped); a non-player character's side is rolled by the system. It needs at least one non-player character, so a fight between two player characters is still run by hand with an opposed roll and `deal_damage`. `/status` in the client shows how hurt everyone is.

Each campaign lives in `campaigns/<name>/` (git-ignored): a `characters/` folder with one JSON file per player character, `state.json` and `transcript.jsonl`, plus an optional `premise.md` that tells the GM what the session is about. The first run writes two demo characters; edit them or add your own. Stop and restart the server and the table picks up where it left off. After editing a character or `premise.md`, restart the server: the GM learns the changes on its next turn, with the story so far intact.

A character sheet (`characters/kira.json`, named after its `id`) holds what the character is: `metatype`, every attribute (Body to Charisma, `edge`, `essence`, `magic`, `resonance`), `initiativeDice`, `skills` with ranks (the keys are `astral`, `athletics`, `biotech`, `closeCombat`, `con`, `conjuring`, `cracking`, `electronics`, `enchanting`, `engineering`, `exoticWeapons`, `firearms`, `influence`, `outdoors`, `perception`, `piloting`, `sorcery`, `stealth` and `tasking`, with ranks from 1 to 12), `specializations` (each a `skill`, a `name`, and `expertise` true for the +3 kind, otherwise +2), and free text for `gear`, `qualities` and `notes`. Enter the final numbers: the game does not apply metatype or augmentation adjustments for you. The sheet is checked when the server starts, so a misspelled field or skill is an error that names the file. How hurt a character is, and their treatments, are kept in `state.json`, so editing a sheet between sessions never changes their wounds. So is the Edge rank a character has burned (`burned`), which comes off the Edge on their sheet whenever the game loads and is never written back to the sheet; the book lets burned Edge be bought back with Karma, which the game does not handle, so to do that lower the number in `state.json` while the server is stopped. Characters are read in order of id. An old `party.json` is no longer read.

The server answers only this machine. It refuses connections that do not come from loopback, requests whose `Host` does not name loopback, and browsers whose `Origin` is not the web app's, so a web page you visit cannot drive the table. The GM process runs in a private folder with no settings files and none of your credentials in its environment. Claude Code still shows the model your account email, and the CLI has no switch to stop that, so the GM is told never to mention it.

## Who it is for

One owner, on their own machine, with their own Claude login. The group plays around that one laptop and everything is typed on the owner's keyboard. There is no remote or multi-device mode, and no player logs in with their own account.

## Rules

The engine follows the Shadowrun 6th Edition core rulebook. Its numbers are in `server/src/data/sr6/ruleset.json`, and the Edge boosts, actions and burns with their costs are in `server/src/data/sr6/edge.json`. Both name the rulebook PDF page each value comes from, so any of them can be checked; rules the engine applies in code are listed with their pages under `rulesInCode`. Edit the files to change a rule; they are validated each time the rules load. The `unverified` list in the ruleset names the few rulings the engine makes where the book is silent.

Keep your copy of the rulebook in `docs/rules/`. Git ignores that folder, so the PDFs are never committed or published.
